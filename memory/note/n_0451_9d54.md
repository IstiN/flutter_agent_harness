# Note: n_0451_9d54

Mailbox liveness architecture (commit ac01bc38): TWO MailboxEntry types by design — flutter_agent_harness core (lib/src/messaging/messaging_repository.dart; carrier of MessagingRepository: FileMessagingRepository, agent_directory tool, app fabric) and fah_hub_client's (hub-client surface); independent packages, semantics mirrored, no dedup. agent_directory lists LIVE boxes (lastActivity within 15-min default window, source-defined) + pending>0 + self + subagent handles; graveyard behind all:true; liveness = .heartbeat marker + inbox/read file mtimes (.id/_scheduled excluded), refreshed by host inbox-watch timers (CLI ~4s, app ~6s). Mixed fa versions degrade to last-mail mtime. PARKED follow-ups: (1) auto-clean of stale 0-pending mailboxes after N days (no destructive prune yet); (2) hub join — hub-backed boxes could take lastActivity from fah_hub_client>=0.2.4 roster lastSeen (activity-accurate since dap v0.3.1) instead of file mtime; zero hub-side work needed.
