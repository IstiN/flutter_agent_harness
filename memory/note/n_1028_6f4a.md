# Note: n_1028_6f4a

crap4dart CRAP ratchet (threshold 12.0 in crap4dart.yaml) fails on the repo MAX CRAP only — "Max CRAP: N — FAIL (threshold: 12.00)", one "threshold exceeded" line for the max offender. A method at exactly CRAP 12.00 passes; >12 fails. CRAP = CC²×(1−cov)+CC, so a fully-covered method still needs CC ≤ 12 (coverage can't save CC 14) — split the function. Local CI parity recipe: dart test --coverage=DIR (<targets>), dart run coverage:format_coverage --lcov -i DIR -o DIR/lcov.info, python3 scripts/merge_lcov.py -o coverage/lcov.info <shards>/lcov.info (it SUMS DA hits per (file,line) — never merge tracefiles from runs over DIFFERENT file content; strip stale SF blocks first), then dart pub global run crap4dart analyze + check --baseline. Gotcha that caused gh-2178's CI red: a scan tracking depth increments on `{` so a JSONL record's top-level keys sit at depth 1 — comparing depth==0 makes the branch unreachable dead code (0% cov → CRAP blowup).
