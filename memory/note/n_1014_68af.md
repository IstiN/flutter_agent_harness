# Note: n_1014_68af

Testing the CLI TUI (useTui: true + tuiProgramHooks): `tuiSubmitForTest` drives `_handleTuiSubmit` directly and BYPASSES the model's `_submit` echo — the submitted text never renders unless a later code path paints it, so assert effects (e.g. a composer restore via sendInputText), not the echo. Frame output is coalesced (~16ms flush timer) behind host futures: after `await submit`/settle, POLL frames with waitForIt before asserting frame content — a direct expect races the paint and flakes. The boot-cap defer note (`compaction deferred to the first message`) prints BEFORE the TUI owns the io (session boot precedes _runTuiRepl), so it lands in io.out, never in frames. Esc key injects fine as `keys.add([0x1B])`; ctrl+c quit needs the double-press `[0x03],[0x03]`.
