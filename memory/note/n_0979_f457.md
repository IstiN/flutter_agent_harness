# Note: n_0979_f457

dart-test runner-zone landmine: `unawaited(future.catchError(handler))` on a `Future<T>` that ALSO has a `.then(onValue, onError:)` listener can fail under the `dart test` runner zone with "The error handler of Future.catchError must return a value of the future's type" — even though the handler runs and returns a valid T (root-zone scripts do NOT reproduce it; the delivery path differs under the runner's StackZoneSpecification). Seen in gh-1054's `_supervisedAttempt` zombie guard (`unawaited(inner.catchError((_) => ToolExecutionResult.text('')))`) the first time a supervised executor actually ERRORED post-cancel; every prior test used never-completing zombies so the guard never fired. Fix: the guard was redundant — the `.then(onValue, onError:)` waiter registered right after already consumes the error; deleting the catchError removed the failure for all 18 supervisor tests. Rule: never attach a second (unawaited) catchError to a future that already has a then-error listener; if a runner-only catchError-type error appears, look for the redundant guard first.
