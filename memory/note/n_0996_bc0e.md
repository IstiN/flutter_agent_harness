# Note: n_0996_bc0e

PR-rework verification recipe (gh-1446 round, 2026-10-09): (1) a fresh runner checkout reports ~100k dart analyze issues until `flutter pub get` runs (unresolved package URIs); CI's gated view is `dart analyze lib test bin` (plain `dart analyze` + the scoped form are the ci.yml static legs) — compare branch vs an `origin/main` worktree issue lists (sorted) to prove "0 new issues", ignoring same-file line-number drift. (2) When a review thread demands `dart format`: run it ONLY over the PR-touched files, and first check which of them were ALREADY unformatted on main (dart format --set-exit-if-changed per file in an origin/main worktree) — for gh-1446 that was 13 of 44 touched files; reformatting those is out-of-scope churn, so leave them at main's formatting (the branch's unformatted-file set then equals main's = zero new regressions, which is the reviewable claim). (3) The WIP auto-save pre-commit hook (dart format self-heal) may collapse/split manual formatting to canonical tall style — always `dart format --output=none --set-exit-if-changed <file>` after the bot commits instead of trusting your hand-written layout.
