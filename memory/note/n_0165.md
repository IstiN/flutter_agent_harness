# Note: n_0165

fa v0.1.223 (typing UX-perf card): (1) INPUT-FRAME PRIORITY in vendor dart_tui program.dart — batches containing KeyMsg/MouseMsg force render() past the fps throttle (render(buildView, {force})); non-input frames still drop+defer. Measured echo latency during 500-delta/s stream on 20k-line transcript: p50 12-17ms → 0.1-0.2ms, p95 ≤0.4ms, paint rate ~100/s unchanged. Tests: vendor/dart_tui/test/input_frame_priority_test.dart (assert AFTER program.run — expect inside unawaited closures silently kills the quit and hangs the test 30s). (2) Ctrl+C = /exit semantics: SIGINT interactive → abort (bounded AgentCli.waitForIdle 5s) + persist + sessionResumeHint() printed to REAL stdout (new public getter; io-routed hint dies with the TUI — that's why /exit showed it and SIGINT didn't) + exit(130); Esc = abort-without-exit; sigintAction simplified to exitInteractive/exitHeadless. Perf-tool landscape: crap4dart 0.9.4 HAS `profile` (instrumented tests, per-method timing; user tip!) — its TOTAL column overflows on 10^10+ calls, but %/MEAN/CALLS ranking is real; confirmed markdown inner loop (consumeLine/formatLine/tuiTextWidth/wrapAnsiLine ~70% of test time) is THE hot path, kept O(delta) by the incremental sync. FA_TUI_TRACE remains the runtime ground truth (build_us/render_us per frame). View windowing already O(viewport) — no 5k-row walk per frame; the old 12ms echo was pure frame-throttle queueing, not CPU.
