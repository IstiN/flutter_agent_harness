# Note: n_0222

fa v0.1.237: (1) status bar 'openai/glm… although user picked z.ai' ROOT CAUSE: Model.provider carries the CATALOG PROTOCOL KIND ('openai' for any openai-compatible entry — saved entries store spec of their preset, _switchProvider pins ModelRef(provider: spec.name)); the ENTRY NAME (z.ai/codemie-personal) lives only in _activeCustomName. FIX: _statusProviderLabel(model) in approval_commands.dart resolves config.customProviders entry by baseUrl (_sameEndpoint, trailing-slash tolerant) → entry.name, else model.provider. (2) 'reopened fa and got gemini-3.7 from old codemie test' ROOT CAUSE: _recordCustomModel had `if (active == null) return;` BEFORE onModelChanged — /model switches on CATALOG providers (active==null) never fired the host persist (bin/fah persistConfig writes modelId from cli.agent.state.model on onModelChanged) → restart restored the stale config model. FIX: always fire onModelChanged; updateModel stays conditional on an active entry. NOTE (open card): CliConfig persists only providerKind (yaml 'provider'), NOT the catalog provider NAME — restart rebuilds by kind and loses 'zai' name (label fix masks it when an entry matches baseUrl; pure-catalog restarts still show kind).
