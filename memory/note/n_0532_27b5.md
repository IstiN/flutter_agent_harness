# Note: n_0532_27b5

CPU burn investigation (fa CLI agents): idle `fa` processes burn 37-100% of one core for hours. Confirmed on PIDs spawned by YoLoIT.app (fd 3r = YoLoIT flutter_assets, launched from the app's embedded terminals) and on a plain `nohup script -q /dev/null fa --session X` probe (real HOME, cwd /tmp) which was quiet for ~50min then started burning. Boot-wedge signature: the burning probe wrote NO fa.log boot line, NO session file, NO mailbox — wedge happens very early in boot. AOT binary ~/.local/bin/fa is stripped (atos gives no symbols); hot frames sit in an rwx VM_ALLOCATE JIT region (ffi trampolines?) + VM runtime offsets 0x19xxxx-0x26xxxx; EventHandler thread busy in Dart_PostCObject. NOT the cause: transcript size (2.4MB/300K-char lines boot+idle quietly), turns on big transcripts (quiet), memory maintain (stores empty), inbox polling (tiny dirs), compaction retries (bounded 3+backoff), TUI render cache (incremental, identity-keyed). AOT rejects --observe; profile from source via dart run --observe + tool/boot_wedge_profile.dart (vm_service getCpuSamples). Live canary: /tmp/fah_wedge_home + nohup script fa --session wedge_canary --session-root /tmp/fah_wedge_root (pid ~27601).
