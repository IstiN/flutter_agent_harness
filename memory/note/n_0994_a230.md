# Note: n_0994_a230

ci.yml "CRAP + duplication" (guards) job step order: (1) dart pub global activate crap4dart >=0.11.0 <0.12.0 + `crap4dart analyze` (CRAP ratchet, reads coverage/lcov.info merged from core-test shards), THEN (2) `crap4dart check --baseline` (loc ≤2800 + duplication + broken_goldens). A CRAP failure exits at step 1, so a loc-gate violation (file >2800 lines) stays HIDDEN — always run `crap4dart check --baseline` locally when fixing the CRAP step, or the job fails a second time. Local CRAP reproduction: subset `dart test --coverage=<dir> --exclude-tags integration <wheel-touching files>` + `dart run coverage:format_coverage --lcov -i <dir> -o coverage/lcov.info` + `dart pub global run crap4dart analyze`; per-function CC/coverage then matches CI full-suite numbers for functions only those files exercise (e.g. _handleMouseWheel). `view`-style frame builders need the FULL suite for 100% coverage — subset coverage understates them.
