# Note: n_1012_96d1

Release-train recovery playbook (gh-1845, 2026-10-24): when a v* tag run's "Sign release checksums" (release-provenance) fails with "release <tag> is missing 1 required asset(s): fa-extension.zip — BLOCKING the publish", the fix is NOT code: dispatch the producer with an explicit tag — `gh workflow run build-macos.yml --ref <tag> -f version=<tag> -f create_release=true` (its build-extension job is ubuntu-latest, fast, and adopts the existing draft via scripts/release_lazy_draft.sh) — wait for fa-extension.zip to appear on the release, then `gh run rerun <tag-run-id> --failed`. Root pattern: build-macos.yml build-extension derives "latest+1 at its own dispatch moment" and runs ~once daily, so any tag train landing after the daily leg has no fa-extension.zip and the gh-1832 gate correctly strands it as a draft (seen stuck: v1.0.637, v1.0.638 on 2026-10-24). "Advance vpinned marker" failing right after is downstream noise (pin_release.sh refuses to pin unsigned releases) — it self-heals once provenance lands. Note: gh run view --json jobs returns only the latest attempt; failed release-tail jobs may be absent from a stale ci-red ticket's job list if the report was filed before the tail finished. Also: a rerun --failed never resurrects SKIPPED jobs (e.g. Installer smoke) — benign, the Quality gate treats skipped as neutral. Systemic fix (follow-up gh-1847) LANDED the same day: the tag train builds fa-extension.zip itself (ci.yml build-extension, an additive continue-on-error leg mirroring web-spa; release-provenance needs it so the gh-1832 gate never races the attach), so a draft stranded on the missing zip now self-heals with a plain `gh run rerun <tag-run-id> --failed` — the manual producer dispatch above survives only as the fallback for a red or flaky extension leg, and the daily build-macos leg was kept as the next-tag-draft pre-stager.
