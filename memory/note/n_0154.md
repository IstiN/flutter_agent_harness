# Note: n_0154

fa TYPING-LAG ROOT CAUSE (fixed v0.1.221): streaming deltas WITHOUT trailing newlines grow the transcript's LAST line into a NEW string each flush; TranscriptMarkdown.sync's resumable check requires identical(src[_through-1], _boundaryLast) → identity break → FULL format+wrap rebuild (~220ms on 300×2000-char lines) EVERY flush → UI loop saturated → keystrokes queue (typing impossible while thoughts stream). Reproduced end-to-end: PTY driver (/tmp/fa_lag_driver.py, FA_TUI_TRACE) + manufactured 150k-token session (/tmp/gen_big_session.py; sandbox root /tmp/fa_lag_sessions, switch via /session <id> — NOTE: CLI --session <id> failed to match, /session works) → trace showed 260ms builds at ~1.2Hz cadence during stream; bisect (tool/frame_build_bisect.dart, shipped): honest appends 1ms/0 rebuilds, grow-last was 4327ms/21 rebuilds → after fix 15ms/1. FIX: TranscriptMarkdown._rollbackGrownTail — when the boundary line strictly grew (startsWith + longer), roll durable caches back ONE source line (new per-source-line _srcFmtStarts/_srcRowStarts arrays + _fenceBeforeBoundaryLine from new _WalkResult.fenceAfter) and resume; replaced/shrunk/front-trimmed tails keep the safe rebuild. Tests: 'streaming tail growth (no-newline deltas)' group in transcript_markdown_perf_test.dart. IMPORTANT diag lesson: the OLD-ctx-memo (0.1.219 fix) was NOT the typing-lag cause — estimateContextTokens(150k)=0ms; the wrap pass was. Session storage: macOS default root ~/Library/Group Containers/group.dev.fa1.shared/fa/sessions/<cwd-slug>/; CLI resume only via --session name/id (list spans slugs) or /session; /ctx in piped line-mode crashes on terminal-size ioctl (small open bug, unfixed).
