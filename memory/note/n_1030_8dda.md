# Note: n_1030_8dda

flutter_agent_harness landing-page deep-link contract (gh-1832/gh-2194): scripts/assert_release_assets.sh --landing probes every releases/(latest/)?download/ URL in site/index.html, but ONLY on the tag train — PRs can land rotting latest/download links and the breakage surfaces as a red release run hours later. Contract now pinned offline by test/site/landing_deep_links_test.dart: every latest/download deep link must name an asset from scripts/release_required_assets.txt. Daily-leg app assets (fa-app-windows-x64.zip/.msix from build-windows.yml, DMGs, APKs) are clobber-refreshers, never in the required set — the landing page must reach them via the release PAGE link (macOS-button pattern), never latest/download deep links. Fixed on ai/gh-2194 (site/index.html windows block + guard test + CHANGELOG Unreleased entry).
