# Note: n_0164

fa Ctrl+C "hang" RESOLVED (v0.1.222, commit a01d1f0): Ctrl+C mid-stream is delivered as SIGINT (isig stays enabled — 0x03 NEVER reaches the TUI as KeyMsg; PTY traces: no stdin event, loop alive and painting). Old handler: busy → fireInterrupt (abort run) with NO output → silent screen = "looks hung". NOT a hang: 2nd press while idle exits 130 instantly. Fix: busy press now ALSO prints 'run aborted — press Ctrl+C again to exit' via io.writeln (lands in TUI transcript); mapping extracted to lib/src/cli/sigint_action.dart sigintAction({busy, headless}) → {abortRun, exitIdle, exitHeadless}; PTY-verified end-to-end (hint after press 1, exit 130 after press 2; abort settles in ~4-8s on glm). Compaction "235s" spinner = REAL pass: 200k+ token session summarized by glm-5.3-flash takes minutes (fa.log: 210925→26742 ok), bounded by 5-min stream-idle watchdog; one 19:20 timeout then retried ok. Perf residual after 0.1.221: ~12ms/frame echo on 5k-row transcript + one 264ms one-off build at big-session load — acceptable. PTY probe infra: /tmp/fa_exit_driver.py, /tmp/fa_hang_probe.py; FA_TUI_TRACE shows 'stdin'/'batch'/'paint'/'drop' events; dart run clone boot needs ~35s in PTY probes.
