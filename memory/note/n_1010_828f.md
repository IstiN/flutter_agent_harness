# Note: n_1010_828f

gh-1801 fix (2026-10-23): the release train's empty-latest-release creators were auto_release.sh (`gh release create --latest` with ZERO assets on every main-push train — the fa update 404 window) plus asset-less lazy creates in ci.yml binaries/web-spa and build-macos.yml CLI/extension jobs. Fixed by removing the auto_release create entirely (binaries job owns creation) and making every lazy create DRAFT-first with `--draft=false --latest` only in steps that upload a real fa-*.tar.gz/zip; release_attach_or_create.sh's attach path now publishes drafts too. Invariant pinned by test/release_empty_latest_guard_test.dart (no release may become latest without a CLI asset). FORENSICS LESSON from the same ticket: the filed "mobile legs cancel each other via shared concurrency" was WRONG — build-mobile run 39905802767 was killed by its OWN 90m build-ios job ceiling (check-run annotation "exceeded the maximum execution time"), the sibling had finished 78 min earlier, and the #351 group is per-run_id with cancel-in-progress:false; ALSO the job declared runs-on [self-hosted, macos-m5, fa-m5-1] yet executed on fa-m5-2, so that runner carries a stale fa-m5-1 label in GitHub runner settings (repo code cannot fix; gh-1692 routing contract). Before blaming concurrency for a "cancelled" run: check the job's check-run annotations (timeout kills report conclusion=cancelled) and compare the sibling's completion time.
