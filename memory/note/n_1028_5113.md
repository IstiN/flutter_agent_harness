# Note: n_1028_5113

Release-hygiene sweep tickets ([daily-publish] stale release drafts swept, label release-hygiene, e.g. gh-537/664/1064/1899/2008/2026/2038/2105/2150) are auto-filed daily by scripts/sweep_stale_drafts.sh and auto-close on the next clean sweep. Classification playbook: (1) the sweep itself already DELETED the stale draft — the hygiene action is done the moment the issue is filed; (2) the "Failed tag trains named above" section names the real blocker: check that train run's failed jobs — `Advance vpinned marker` red is ALWAYS downstream noise (pin_release.sh refuses unsigned releases, E_PIN_PROVENANCE_MISSING), `Quality gate` red is the aggregate of a real leg; find the real root cause in that leg's job log (gh run view --job <id> --log; xcodebuild output needs --allow-escape-sequences or the gh api jobs/<id>/logs form, else ANSI-filtered lines vanish); (3) if the root cause already has a merged fix PR + in-tree pin test (gh-2106→PR #2109 wasm_run LIBRARY_SEARCH_PATHS; gh-2134 checkout-scoped DerivedData wipe; sqlite3 prewarm contract), the correct leg outcome is outputs/already_fixed.json + NO PR; (4) NEVER rerun a superseded tag train — publishing a superseded tag gives it a fresh created_at, floating it above newer releases on the releases page; "rerun the train" is an owner decision only while the tag is the newest. The "recurrence means a lifecycle guard is missing" prose is the sweeper's canned pointer to #282 — the guard EXISTS (the sweeper is the guard); failure-time draft deletion would break rerun recovery (binaries adopt the existing draft). Diagnosing tips: sweep threshold is >24h so a draft created just after a sweep is filed only two days later (expected); v1.0.7xx train job logs on fa-m5 self-hosted macOS runners often carry gh-2134: wipe lines.
