# Note: n_0976_f1a2

gh-968 fixed (resume parity budget + record-granular stop): the CLI resume walk's tokenBudget was window − reserve (transcript-only), so a resume filled the resident records to ~the window while the ctx meter added the unanchored system+tools overhead (~8.5k) on top → meter read >100% (the reported `127%/200k` footer) and tripped the guard/auto-compaction on a fresh resume. Fix (3 points): (1) `resumeParityBudget()` in token_estimation.dart = effectiveContextWindow − estimateRequestOverheadTokens(systemPrompt, tools) − CompactionSettings.reserveTokens, floored at 0 — consumed in `_loadSession` with `_effectiveCompactionSettings` (honors the config override); (2) `projectedBranchBudgetCut()` — the exact mirror of estimateProjectedBranchTokens walked NEWEST-end backward (markers sit newer than what they hide; classic transform prices everything below the last compaction record at zero); (3) `WindowedSessionStorage._trimTokenBudget` — on a budget stop, drops oldest resident records to the cut (stop-BEFORE the crossing record → kept tail ≤ budget, overshoot bounded by one record never one doubling block), restores `_hasOlder`, never touches the tail anchor, keeps ≥1 record (budget-0 floor). Boundary-first preserved: a resident compaction boundary still wins over the budget and is never trimmed. Both CLI entries (run/runHeadless) share `_loadSession` → AC-R0 equivalence by construction. Tests: token_estimation_test (resumeParityBudget/projectedBranchBudgetCut groups), windowed_session_storage_test (trim/boundary-first/floor/Cyrillic+image), test/cli/agent_cli_resume_parity_test.dart (IT-EQUIV/IT-NOGUARD/E1-127%/E4-cap/E5-double-resume/AC-R3-override; E1 test verified to FAIL against the old budget).
