# Note: n_1017_b105

CI flake root cause (gh-1903 dispatch watcher, 2026-10-29): bash 5.3 on ubuntu-26.04 runners can kill a signal-trapped script with `trap: line 2: unexpected EOF while looking for matching ')'` + exit 2 BEFORE the trap handler runs. Mechanism (bash source-verified): run_pending_traps() fires from input.c getc_with_restart and eval.c parse_command:34 while the shell's parser holds a half-read construct; the trap ACTION STRING is then parsed via parse_and_execute in that poisoned state (only the line number resets, and run_pending_traps' generic TERM path has no reset at all), parser_error → exit_immediately_on_error (set -e) → exit_shell(2). Hit main's own run 40857595467 (b54f324c, TERM test) and PR #1958's head 6a49b3ec (INT test) within one hour — load-dependent, ~270 unloaded local reproductions failed to hit it. Fix pattern: never let gh-1903-class containment depend solely on a bash trap action; dispatch_and_watch.sh now spawns a detached `--dw-orphan-backstop` re-invocation of itself (setsid where available) with a state-file handshake (handler-ran marker written FIRST, child-started flag) so the cancel happens exactly once even if the trap parse dies. Deterministic repro without load: an intentionally unparseable trap action string (e.g. `trap 'handler TERM ( ' TERM` — bash does NOT validate trap strings at install time, only at fire time). Also: this repo's branch auto-save machinery commits WIP every ~5 min and merges moving main into agent branches mid-task — check `git log` before staging so a "missing" file diff is understood before re-adding.
