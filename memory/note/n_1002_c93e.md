# Note: n_1002_c93e

flutter_agent_harness coverage-measurement gotcha (pr-1730 rework): the pty-coverage-gate CLI ratchet (scripts/check_cli_coverage.py vs scripts/cli_coverage_baseline.txt) measures lib/src/cli/** coverage ONLY from the pty-integration-linux leg's dart test --tags integration run — coverage comes from tests that IMPORT lib code in-process; subprocess CLI boots (FA_BIN/dart run bin/fah.dart) contribute ZERO measured coverage. Untaged test/cli suites never count. To raise the measured number: add integration-taged test files (they bin-pack into a shard at runtime via shard_files.py; check_llm_tag_boundary.py must stay at 0 violations — MockLlmServer/127.0.0.1 markers exempt mock files). To verify a ratchet delta WITHOUT running the 40-min leg: gh run download <run> -n pty-coverage-shard-{0,1,2} (must run gh inside the repo dir), union-merge the three lcov.info files (max DA hits per line), compute lib/src/cli hit/total, then union your new suite's local coverage (dart test --coverage + coverage:format_coverage) on top. The margin over the baseline can sit under ~0.2pp run-to-run PTY variance (pty_harness git-inits a short cwd per spawn partly because of this) — leave a guard band (repo precedent: floor at measured − 0.02..0.85pp, gh-1259/#1565); never lower the baseline (only-up ratchet).
