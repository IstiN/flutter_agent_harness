# Note: n_1027_c35c

Shell-job near-miss test fixtures: NEVER build a stale id by blind-suffixing a minted id (e.g. `entry.id.substring(0, len-2) + 'zz'`) — `newShellJobId`'s random base36 tail ends in 'zz' once every ~1296 starts, the "stale" id then IS the exact id, and lookup rightly answers `ShellJobHit` instead of `ShellJobNearMiss` (loud red in `shell_jobs_test.dart` AC1 and 2 of 3 `bash_job_resolution_test.dart` AC1 fixtures, silent coverage loss elsewhere). Incident class hit twice: red main run 38120494810 (AC5 stop test) and tag-train v1.0.708 run 43006085893 → gh-2113 (hostile-env leg, 1 failure in 13,775; also failed the `Quality gate` aggregate and cascaded `Advance vpinned marker`). Fix (test-only, commit f2f8d58 on ai/gh-2113): force the retained id with `env.forcedIds = ['sh-1-aaaa']` before `registry.start` in ALL near-miss fixtures — the idiom is commented in-place at all four sites; extend the same treatment to any new near-miss fixture.
