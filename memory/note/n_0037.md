# Note: n_0037

App→CLI attach delivery bugs fixed (Aug 26): (1) session-storage fallback (~/.fah/sessions when Group Container unwritable) did NOT move the messaging fabric — SwappableMessagingRepository added to lib/src/messaging/file_messaging_repository.dart; AgentCli._createSession fallback calls _fabricRepository.swap(). (2) Inbox-wake cap (_maxInboxWakeStreak=10) silenced the CLI after ~10 app-driven messages because only typed input reset it and the reset lived inside the run the gate refused — _wakeOnInboxMail now peeks pendingInbox() and exempts/resets on kind==user messages; inboxWakeStreakForTest seam added. (3) AttachedSessionController.send swallowed errors — lastSendError field added. (4) flutter_app drawer attach now derives sessionsRoot+cwdSlug from the session JSONL path via sessionRootAndSlugForPath (cli_session_presence.dart) instead of guessing from manager default root. Tests: test/cli/agent_cli_attach_test.dart, test/messaging/swappable_messaging_repository_test.dart, flutter_app/test/attach/*. Historical diagnosis: zero 'fromId":"app' message files ever existed under the shared roots — the old symptom came from pre-attach app builds acting as second JSONL writers; restart 'fixed' it because resume replays the whole transcript. Both fa binary AND Fa.app must be rebuilt together (same version) or mailboxes/sessions split again.
