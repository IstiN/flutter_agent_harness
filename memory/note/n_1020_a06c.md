# Note: n_1020_a06c

fa_network aggregate inbox API live in prod (PR #17, squash 5641e6b): GET /api/inbox + PATCH /api/channels/{id}/read on https://network.fa1.dev, OpenAPI 0.2.0. Key facts: (1) read cursors are per-USER in channel_reads(user_id, channel_id, seq), monotonic + clamped to channel max; (2) unread baseline materializes lazily on the user's FIRST GET /api/inbox (anchor = current max seq, no historical flood); (3) /healthz on network.fa1.dev returns GFE's own HTML 404 — Google Front End intercepts the path before the service (same on the direct *.run.app URL); use /api/networks/public (200, hits DB) or /api/inbox (401) as practical healthchecks; (4) fa_network pre-commit gate is crap4go (bin/crap4go, threshold 12) — uncovered PG code must keep CC ≤ 3 per function (CRAP = CC² at 0% coverage); (5) deploy is automatic on push to main (deploy.yml, ~4 min, quality gates + Cloud Run).
