# Note: n_0984_1f08

gh-1054 rework round 3: "Quality gate" in ci_failures.md is only the AGGREGATE — fetch per-leg results via `gh api repos/OWNER/REPO/actions/runs/<id>/jobs --paginate --jq '.jobs[] | select(.conclusion=="failure") | .id'` (logs need `--allow-escape-sequences`); on this round the real legs were Static gates + Core shard 0 + PTY shards 0/1. The #1 Static-gates breaker is the repo-wide 2800-line file cap (`find lib test example -name '*.dart' ... -gt 2800`, scripts/ci_fast_gate.sh MAX_LINES) — agent_loop.dart (3179) was fixed by extracting the stuck-supervision subsystem (~650 lines) into a `part of` file `agent_loop_stuck_supervision.dart` (agent_cli.dart's 10 part files are the repo convention); builtin_tools.dart (2803) by moving the soft-yield hand-back text builder into stuck_tool.dart as `stuckBackgroundHandbackText` (re-exported via agent_loop.dart's `export 'stuck_tool.dart' show` list). Also: `dart analyze` at repo root fails with office_addin errors until `cd office_addin/dart && dart pub get` — pre-existing local-env artifact, not a branch break (CI passes because its checkout resolves it). CI flake triage recipe: compare the failing test against main's LATEST green ci.yml run on the SAME sha (gh api workflows/ci.yml/runs?branch=main) — main's own runs flake on different legs (redact/perf_test.dart), proving runner-load flakiness. AC5 REPL-parity flake fix pattern: never poll a growing session JSONL via JsonlSessionRepo from outside (repo.open takes the lock the live REPL appends under every heartbeat — 50ms polling starves the watched leg, exhausting even a 90s budget); poll the raw file text for the terminal record (`"action":"escalate"`) at 250ms cadence instead, and compare collapsed heartbeat runs (consecutive same-attempt heartbeats → one) not raw counts.
