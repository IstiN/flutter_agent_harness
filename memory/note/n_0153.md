# Note: n_0153

fa mixing + typing-lag root cause CLOSED (v0.1.220): both were the SAME cause — stale fa processes (pre-13:18-fix binaries, e.g. PID 8364 started 17:37, pre-0.1.219 install at 20:24) sharing the repo cwd. (1) bash output poisoning = old sh-N.log job-log collisions (code fix 4612a636 in 0.1.219); (2) typing lag = old ctx memo keyed on streamLen → O(context) estimateContextTokens per frame while streaming (fix SettledContextEstimate in 0.1.219). Evidence: end-to-end PTY probe (/tmp/fa_lag_driver.py, FA_TUI_TRACE) on installed 0.1.219 with real provider stream (900-word essay): key→paint p50=0.2ms/p90=18ms while streaming, heaviest frames ~6ms; controller-level probe (tool/key_latency_probe.dart, shipped in 0.1.220): 20k-line transcript + 500 deltas/s + 800-line bursts → p95 18ms. Detection shipped: ShellJobRegistry.onStaleJobLog — one-per-session loud CLI warning when a fresh old-format sh-N.log appears after boot (isOldFormatJobLogName + mtime>bootTime); wired in agent_cli _onStaleJobLog. Fleet rule: every fa instance must run the CURRENT binary — stale instances now self-announce. Lesson: my own pre-restart harness was ALSO old (my commit job was 'sh-48' old format) — always check job-id shape to detect build skew.
