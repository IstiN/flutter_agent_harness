# Note: n_0989_04c6

CI invariant (gh-1310, 2026-10-06): every flutter_app `flutter pub get --enforce-lockfile` in .github/workflows MUST ride the shared composite action `.github/actions/flutter-pub-get` — NEVER a bare run-step (`cd flutter_app && flutter pub get ...` trips test/ci_pub_get_retry_guard_test.dart). Rationale: pub has NO retry for its git-dep mirror clones (flutter_js, flutter_js_widget_runtime); one transient "Connection reset by peer" on github.com:443 kills the leg, and lockfile-refresh release commits (gh-1299 class) cold-miss the flutter-action pub cache so fresh clones happen exactly at release time — that flake red ci.yml build-macos on the very next main run after #1304 fixed the deterministic lockfile drift. The action carries the #726 bounded retry (3 attempts, 15s backoff) + deterministic-skew fail-fast ("Unable to satisfy ... pubspec.lock" = exit immediately, don't blame the network). Scripts (tag_release.sh, build_browser_ext.sh, build_office_addin.sh) keep their own invocations — they ride the warm pub cache after a workflow-level action step resolved first. Diagnosing tag-run reds: exit 65 = enforce-lockfile skew (gh-1299/#1304), exit 69 = pub git-clone error (transient, now retried); gh-1299's lockfile-drift incident also felled the pure-Dart legs via test/nightly_desktop_leg_guard_test.dart AC2.
