# Note: n_0985_9889

CI triage: the one-liner `File not formatted as yaml: .` in a failed PTY/CLI integration log is the Dart CFE's own error (it lives in the SDK's frontend_server/kernel_worker snapshots, next to "read the 'libraries.json' specification file"), not from this repo or any dependency. It appears when the JIT compile of bin/fah.dart fails to parse the SDK libraries spec on a loaded ubuntu-24.04-arm runner; the spawned CLI then prints nothing else and the PTY test's 90s waitForBoot times out. Known flake class of `PTY/CLI integration (linux, shard 0/3)`: a different victim test each run (pty_resume_equivalence boot hang, job_board_stability, scheduled_indicator — all timeout-waits), hits main's own scheduled runs too. Response per ci.yml watchdog doctrine: empty-commit retrigger / fresh validation dispatch, not a code fix. The "JS engine integration (quickjs-ng)" and "Binaries smoke gate" check runs on a PR are often 0-second synthesized mirrors of the machine-merge bot (PR #N dynamic run) — check their started/completed timestamps before treating them as independent failures.
