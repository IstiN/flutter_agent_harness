# fa — Office add-in (Outlook)

fa as an Outlook taskpane: **the pane IS the fa Flutter web app** (issue
#182) — `flutter_app` compiled for web with the office host flag
(`FA_HOST=office`), served at `https://fa1.dev/outlook/app/` and opened
directly by the manifest. The app embeds the OfficeHostBridge
(`fa_office_agent` package) and exposes the `outlook.*` mail tools, the
full agent toolset (sandbox interpreters included) and BYOK provider
config — feature parity with the browser-extension panel. Classic v1
MailApp manifest plus a `VersionOverrides` command surface (Mailbox 1.8+,
no mobile form factor): an «fa» button on the message Apps flyout /
compose ribbon opens the taskpane — new Outlook for Windows (Monarch) and
modern OWA render command-based add-ins only (issue #143), legacy hosts
fall back to the classic pane.

## Layout

- `manifest/outlook.xml` — Outlook add-in manifest (1.2.0.0): classic
  FormSettings for legacy hosts plus `VersionOverridesV1_0` command
  surfaces (MessageRead + MessageCompose) for Monarch/new OWA. Taskpane
  URLs point at `https://fa1.dev/outlook/app/index.html`; the build's
  `--dev` variant rewrites them to `https://localhost:8443`.
- `dart/` — `fa_office_agent` package (pure Dart, VM-testable):
  `src/manifest.dart` (manifest validator — https + host + `/outlook/`
  path shape, permission ladder exactly `ReadWriteItem`, one Mailbox
  host, no MobileFormFactor, clean XML comments, ItemEdit
  SourceLocation-only, command surface: MessageReadCommandSurface +
  ShowTaskpane, 16/32/80 px button icons, MailHost type, resolvable
  resids; `tool/validate_manifest.dart` is its CLI), the
  `OfficeApi` facade + `JsOfficeApi` (Office.js adapter, web-only) +
  `FakeOfficeContext` (test fake), the three `outlook.*` tools with the
  email-quarantine fence (`src/email_quarantine.dart`), and the
  always-prompt approval overrides.
- `web/` — `index.html` is a redirect shim to `app/index.html` (kept one
  release for sideloaded 1.1.0.0 manifests, then deleted), plus privacy
  and support pages. The real pane page is generated by
  `scripts/build_office_addin.sh`: the Flutter web bundle at `app/` plus
  an injected Office.js script tag and the pane CSP meta.
- `icons/` — taskpane icons (`fa-16/32/80.png` for the command buttons,
  `fa-64.png`, `fa-128.png` for the store/list surfaces).

## Install (sideload)

Full step-by-step guide (requirements, exact UI path, troubleshooting):
[docs/outlook-addin.md](../docs/outlook-addin.md), mirrored live at
https://fa1.dev/outlook/support.html.

Short version — Microsoft removed "Add from a URL" from the manual
surface, so download and add from file:

1. Save https://fa1.dev/outlook/manifest.xml as `manifest.xml`.
2. Open https://aka.ms/olksideload (My add-ins) — works from the web,
   new Outlook, and classic Outlook.
3. My add-ins → Custom add-ins → "+ Add a custom add-in" →
   Add from file → `manifest.xml` → Install.

## Where the add-in shows up

After install the entry point depends on the client (manifest ≥ 1.1.0.0):

- **New Outlook for Windows (Monarch) / OWA**: open a message, click
  **Apps** (…) in the reading surface — the «fa» button opens the
  taskpane. In compose: «fa» sits in the message toolbar.
- **Classic Outlook (Win/Mac)**: «fa» group on the Home ribbon; legacy
  hosts that ignore command surfaces still auto-open the classic pane
  when a message is selected.

Sideloaded installs re-add the manifest after a version bump; store and
centralized deployments re-fetch automatically.

## Dev loop

```sh
bash scripts/build_office_addin.sh --dev   # validates + builds the app (FA_HOST=office) + assembles build/pages/root/outlook/ (dev URLs)
# serve the assembled dir on https://localhost:8443,
# then sideload build/pages/root/outlook/manifest.xml
```

The app bundle is mandatory: the pane has no other surface. The script
needs `flutter` plus the app's gitignored placeholders
(`touch flutter_app/.env; cp flutter_app/firebase_options.template.dart
flutter_app/lib/firebase_options.dart`).

## Security posture (issue #182 decisions)

- **Permissions stay `ReadWriteItem`** (read tier + insert draft body).
  No send, no reply, no folder access — the manifest ladder is pinned by
  the validator.
- **Email quarantine**: every byte out of a mail item (body, subject,
  names, attachment bytes) enters model context only inside the
  `<email-body …>` fence with an untrusted-data trailer; smuggled fence
  markers are neutralized (see `src/email_quarantine.dart`).
- **Always-prompt approvals**: `outlook.read_attachment` and
  `outlook.insert_draft_body` prompt on EVERY call in EVERY session mode
  (overrides outrank mode, turn grants and always-allow);
  `outlook.read_current_item` rides its read tier.
- **Network is T1-only for v1**: the pane calls user-configured provider
  endpoints directly over HTTPS (the web demo already proves provider
  CORS works); no relays, no proxies. The CSP's `connect-src` is open
  for exactly this reason — provider endpoints are user-chosen.
- **Storage is partitioned**: the pane's sandbox FS / settings /
  BYOK keys live in the office origin's IndexedDB/localStorage, fully
  partitioned from the fa1.dev web demo and the extension. Not yet
  `OfficeRuntime.storage` (which survives host cache wipes better);
  documented as a known limitation.
- **Pane CSP** (meta-only, injected by the build): no `unsafe-inline`
  for scripts — helper code rides `blob:` URLs; `script-src` admits the
  Office.js CDN and jsdelivr (quickjs / pyodide / sql.js / on-device
  model runtimes). `frame-ancestors` is NOT enforceable via a meta tag
  and GitHub Pages cannot set HTTP headers — Outlook's own taskpane
  sandboxing is the framing boundary (documented honestly).

## What is tested automatically

- `dart/test/` — the office package: manifest validator (synthetic
  corruptions + committed artifact checks), host-bridge suite, the
  three tools' tiers/notes/quarantine over the fake, approval
  interactions.
- `flutter_app/test/services/office_wiring_test.dart` — the app's real
  boot path: surface + override seeding with/without an api, and a full
  scripted-provider turn reading the poisoned mail body through the
  fence.
- `flutter_app/test/web/owa_sandbox_boot_test.dart` (chrome platform,
  `--dart-define=FA_HOST=office`) — the OWA sandbox reproduction
  ([#202](https://github.com/IstiN/flutter_agent_harness/issues/202)):
  a history-less iframe installs the no-op URL strategy, and the
  onReady-first boot seam memoizes one handshake and fails cleanly into
  `office_unavailable` when Office.js is absent.
- `e2e/` — Playwright chromium + webkit over the assembled pane: app
  boot + office beacon + zero page errors, redirect shim, asset shape
  (no legacy agent, canvaskit mirror), CSP gates (CDN allowed, inline
  refused), IndexedDB FS persistence across reloads, and the
  history-less OWA iframe reaching the first frame.
- CI: `.github/workflows/office-addin.yml` runs all of the above and
  uploads `build/pages/root/outlook/` as the `office-addin` artifact.

A full UI-driven agent turn is NOT e2e-able (canvaskit has no DOM
inputs) — the turn itself is pinned by the Dart suites above.

## Manual real-host checklist

Mocks cannot prove these; verify by hand before a release:

1. **Real Office.js boot** inside Outlook (WebView2 / WKWebView / OWA
   iframe): the sandboxed mock proves the Dart contract, not
   Microsoft's runtime (mailbox readiness, item context, permission
   prompts).
2. **Real sideload + trust prompt**: store/admin policy surfaces
   (publisher trust, "unverified add-in" flows) only exist in a real
   host.
3. **Renderer sanity on the oldest supported WebView2**: the canvaskit
   WASM path in the pane app must render there, not just in current
   Chrome — and the pane CSP must not block anything WebView2 injects
   (styles are `unsafe-inline` for exactly this).
4. **Python/JS sandbox smoke** on the real host: ask the agent to run a
   one-line `python` and `js` snippet; the interpreters load from
   jsdelivr inside the pane (the CSP gate is e2e-pinned, the engines
   themselves need a real run).
