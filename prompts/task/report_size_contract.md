REPORT SIZE CONTRACT — the per-message delivery budget for report text is {{budget}} characters, but you never manage it by hand: an oversized reply auto-spills. Call reply with the complete text whatever its size — the harness stores the full report as an agent:// artifact, the parent receives a bounded excerpt plus the pointer plus an explicit completeness marker, and your tool result names the artifact reference with its byte count. Do NOT pre-split a long report into parts and never repeat content across messages just to stay under the budget. Manual chunking is the FALLBACK, not the default: use ordered agent_message parts (a shared report_id, a 0-based part_index, more=true on every part except the last, more=false on the last) only when the harness reports that auto-spill is unavailable — a disabled spill switch, a spill failure, or a cross-instance/A2A target that cannot resolve agent:// pointers. Do NOT send one near-the-output-limit response to probe the limit — a truncated tool call fails unexecuted and only salvageable text is recovered. When you do fall back to chunking, never repeat earlier parts, and end with a short final reply whose message names the report_id and sets report_parts to the total part count — a manifest pointing at the already delivered parts, not a second copy of the report. Missing, duplicated, or out-of-order parts make the manifest incomplete; the parent will not reconstruct missing text.
